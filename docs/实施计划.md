## 2. 交付范围

### 2.1 本期必须交付

- 一个可通过本地路径和 Git 安装的 Pi Package。
- `/delivery-shape`、`/delivery-plan`、`/delivery-run` 三个 Prompt Template。
- 一个父会话使用的 `adaptive-delivery` Skill。
- 一个窄职责 `delivery-gate` Extension。
- 技术方案确认的状态机、中文显示、批准记录、只读委派、权限策略、writer lease、candidate digest、progress-sync 和断线恢复能力。
- 单一 bundled `pi-subagents` API/runtime owner、重复 owner 检测与真实 run ID 终态摘要重绑定。
- 单元、集成和隔离 E2E 测试。
- README、安装说明、模型配置示例、安全边界和故障恢复说明。

### 2.2 本期明确不做

- 自动训练、微调或自主修改 Package。
- 自动 commit、push、创建 PR、npm 发布或部署。
- 非交互 RPC/JSON/print 模式的审批授权。
- 非 Git 项目、多仓库原子交付和生产操作编排。
- 通用项目计划格式、TODO 系统或 Issue 状态机。
- 自研子 Agent runtime、CI 平台或操作系统沙箱。
- 默认真实模型调用、真实 Provider 出网或费用测试。

## 3. 实施原则

1. 每个 cwd/worktree 同时只有一个 writer。
2. 父会话是唯一编排者；子 Agent 不作产品、授权和发布决定。
3. 每个里程碑先完成最小测试，再扩大到受影响集成验证。
4. 只有已验证的独立事项才能标记为完成。
5. 每完成一个独立事项，立即更新本文件的状态和验证证据。
6. 未完成事项必须标记为`进行中`、`待验证`或`阻塞`，并记录断点和下一步。
7. 运行时权限、路径和来源判断全部失败关闭。
8. Package 只使用 `pi-subagents` 公开 API，不导入其内部实现路径。
9. 测试默认禁网、使用临时 Git 仓库和隔离 `PI_CODING_AGENT_DIR`，不读取用户凭证。
10. 不为未来扩展增加未被当前验收使用的配置面或抽象层。

## 4. 技术栈与包边界

### 4.1 运行时

- TypeScript ESM，由 Pi/Jiti 直接加载，不要求用户构建产物。
- Node.js 最低版本跟随当前 Pi：`>=22.19.0`。
- `@earendil-works/pi-coding-agent`、`@earendil-works/pi-ai`、`@earendil-works/pi-tui` 和 `typebox` 按 Pi Package 规则声明为 peer dependency。
- `pi-subagents` 固定兼容版本放入 `dependencies` 与 `bundledDependencies`，只导入公开 API；manifest 加载它的 Extension 作为唯一 owner，并暴露同版本 Prompt/Skill。
- `beautiful-mermaid` 与 `@resvg/resvg-js` 固定版本作为普通运行依赖，提供无浏览器 SVG、PNG 和字符图；不放入 `bundledDependencies`。
- `pi` manifest 暴露 bundled `pi-subagents` Extension/Skill/Prompt 与本 Package 自身资源。

### 4.2 开发与测试

- TypeScript `tsc --noEmit` 做静态检查。
- Node 原生 `node:test` 承担单元和集成测试。
- 测试仍使用 Node 原生 `node:test`，通过 dev-only `tsx` loader 处理本仓库以及 `node_modules/pi-subagents` 暴露的 TypeScript public API；Node 原生 strip-types 会拒绝处理 node_modules 下的 TypeScript，因此不作为最终测试入口。
- 测试使用临时目录、临时 Git 仓库、受控环境变量和 fake Pi event bus。
- 真实 Pi 进程 E2E 只使用本地 fake provider/runner；真实模型 canary 必须显式 opt-in，且不进入默认验收。

## 11. 阻塞与停止条件

出现以下情况立即标记当前里程碑为`阻塞`，记录断点并停止扩大实现：

- Pi 或 `pi-subagents` 公开 API 无法提供技术方案要求的能力。
- 无法可靠区分 TUI 用户确认与非用户注入来源。
- 无法证明 output、progress target 或 worktree 路径位于允许边界。
- writer process proof、lease owner 或 candidate manifest 状态未知。
- 需要新增技术方案未批准的配置面、兼容层或权限例外。
- 测试必须调用真实 Provider、读取凭证或产生费用。
- 需要 commit、push、发布或外部系统写入但没有相应授权。

阻塞解除后，先更新本计划，再从最后一个已验证断点恢复。
