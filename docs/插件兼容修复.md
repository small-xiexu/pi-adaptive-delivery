# pi-better-compaction 的 Pi 1.1.0 兼容修复

本仓库保存 [pi-better-compaction 0.6.0 的修复补丁](patches/pi-better-compaction-0.6.0-pi-1.1.0.patch)，用于复核和手动应用本机已经验证的修复。上游项目为 [lll9p/pi-better-compaction](https://github.com/lll9p/pi-better-compaction)，采用 MIT 许可证。

这份补丁适用于 `@lll9p/pi-better-compaction@0.6.0` 和 Pi `1.1.0`。补丁以 npm 官方 `0.6.0` 制品为基线；下载时已核对 registry 的 SHA-512 integrity，应用后的三个源码文件与本机已验证安装逐字节一致。Pi Adaptive Delivery 的运行代码不依赖或自动加载这份补丁。

## 修复内容

Pi `1.1.0` 的上下文包含 `system` 消息。旧序列化器把 user/assistant 以外的消息当作工具返回，读取不存在的 `toolCallId`，在 `session_before_compact` 中触发 `Cannot read properties of undefined (reading 'split')`，可能让交付子任务异常退出并保留占用。

补丁修改三个文件：

- `src/serializer.ts`：通过公开 API 保留初始系统正文、命名规则和 Skills，以及后续更新和删除；对齐初始 system 的计数与无签名 assistant ID；明确 thinking/text/toolCall 元素类型。
- `src/types.ts`：准确表达既有记录守卫已经验证的 details 与可用元数据，修正类型推导，保持原检查顺序。
- `src/extension-runtime.ts`：通过公开 Session 条目和当前 leaf 构建上下文，恢复原生压缩；缺少请求体时跳过请求重写。

原始异常及执行收尾记录继续保留。修复插件后，失败交付留下的占用仍由状态面板按现场核对和明确选择处理。

## 手动应用

先确认插件版本为 `0.6.0`、宿主 Pi 为 `1.1.0`，备份已有本地改动。下面命令在插件根目录执行，路径替换为本仓库的实际位置：

```sh
cd /path/to/pi-better-compaction
git apply --check /path/to/pi-adaptive-delivery/docs/patches/pi-better-compaction-0.6.0-pi-1.1.0.patch
git apply /path/to/pi-adaptive-delivery/docs/patches/pi-better-compaction-0.6.0-pi-1.1.0.patch
```

`git apply --check` 失败时应先核对版本、是否已应用和已有改动，不强制覆盖。已经应用这份完整补丁的本机安装无需再次应用。

在当前 Pi 任务收尾后使用 `/reload` 加载修改，或由新启动的 Pi 加载。npm 更新或重装可能覆盖本机补丁；其他插件版本需要重新核对源码和验证。

## 验证证据

在 macOS、Pi `1.1.0`、Node `25.2.1` 上，实际安装源码完成以下验证：

- 定向测试 **14/14**：系统正文与段落、更新和删除、编号、Unicode、thinking 签名、工具配对、缺失结果、记录守卫及持久 Session。
- 原始失败会话：七段系统规则与 **230 个工具返回**完整保留，原始文件和内存消息保持一致。
- 真实 Pi SDK / 临时 Git 集成 **2/2**：V1/V2 压缩、`fromHook` 持久化、原生窗口请求重放、无请求体和普通检查点恢复。
- 插件完整源码严格类型检查：**0 错误**；真实公开资源加载器冷加载实际入口：**1 个扩展、零错误**。
- 本补丁在 npm 官方 `0.6.0` 的三份原始文件上通过 `git apply --check`，应用结果与上述已验证安装逐字节一致。

模型和压缩客户端均使用替身，没有调用真实模型或压缩服务。具体执行结果见唯一台账 [实施计划第 13.155 节](实施计划.md#13155-本机压缩插件的-system-消息修复)。本仓库保存补丁和说明；用户原始 Session、测试私有目录和 Provider 配置不上传。
