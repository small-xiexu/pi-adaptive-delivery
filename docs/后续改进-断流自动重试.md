# 后续改进：模型断流自动重试

## 状态与排期

- 状态：需求已记录，暂不实施；候选方案尚未完成端到端验证。
- 用户意图：遇到模型断流时自动重试，成功后继续当前任务，减少手动输入“继续”。
- 排期：先完成现有技术方案与实施计划的开发、验证和收口，再重新评估本事项。
- 本次授权仅为新增记录，不包含功能实现、修改 Pi 安装包或用户配置。

本文是后续改进备忘，不是第二份技术方案或开发进度台账，不改变当前开发范围。当前设计仍以 [技术方案](技术方案.md) 为准，开发进度只记 [实施计划](实施计划.md)。后续取得实施授权时，再将必要设计与实施项纳入这两份文档，不在本文另建进度表。

延后处理可以减少与尚未收口的父子会话、取消及 writer 交接逻辑交叉修改；届时也应先确认新版 Pi 是否已经修复，避免实现不再需要的补充逻辑。

## 现象与已有证据

用户提供的截图显示 `Error: stream_read_error`，当前任务随即停止。用户反馈近期频繁发生，但每次在原会话输入“继续”后通常可以正常执行。

前次只读取证与离线函数检查确认：

- 本机 Pi `0.85.1` 的 `isRetryableAssistantError()` 对单独的 `stream_read_error` 返回 `false`，对 `fetch failed`、`terminated` 和 `500 Internal Server Error` 返回 `true`。
- 当时读取到的全局有效默认值为启用自动重试、最多重试 3 次；错误未被识别为可重试时，增加次数不能解决漏匹配。
- Pi 公开文档允许 `message_end` handler 返回同角色的替换消息；已核对实现顺序，该处理发生在消息持久化及后续原生重试判断之前。本地 SDK `0.84.4` 与 CLI `0.85.1` 均存在该接口。

证据限制：截图未确认当次 Provider、完整请求错误或 Pi 版本；全局默认值不等于当次会话配置。手动继续可恢复支持“瞬时故障”的判断，但不能证明具体断流根因。模型服务端、中转网关及网络链路均未定位，也未验证 Package 接入后的实际恢复行为。

## 目标与边界

目标行为：

```text
模型响应流读取失败
  → 按现有重试策略等待并重试失败的模型请求
  → 成功后继续当前任务
  → 次数耗尽时保留错误并停止
```

- 初始范围只处理已观察到的 `stream_read_error`，不把所有错误统一改为可重试。
- 沿用 Pi 的重试开关、次数上限、退避、状态提示和取消行为，不强制开启、不无限重试。
- 用户主动取消后不自动续跑；不注入伪装成用户输入的“继续”，不生成或扩大批准。
- 不主动重放已经完成的工具或整项委派；保留已落盘修改及原生工具结果。
- 不把进程崩溃、父子 RPC 失联、记录写盘失败、权限或 writer 归属不明纳入自动续跑。
- 不承诺消除底层断流，也不将其当作完整的崩溃恢复能力。

## 候选最小方案

优先评估在现有 Extension 的父子公共入口注册 `message_end` handler：仅对符合范围的失败 assistant 消息，保留原始报错并附加 Pi 可识别的重试说明，保持失败状态，交给 Pi 原生重试流程处理。

当前已检查的分类器依赖 `errorMessage` 文本，不是通过公开的 `retryable: true` 字段控制。文本补充是待验证的接入方式，不是 Pi 对该错误的正式分类契约；实施前必须按届时版本复核。仅使用公开 API，不导入私有路径、不修改 Pi 内部状态、不包装 Provider 或重写 Agent 循环，也不新增重试调度器、配置面或状态账本。

父子入口共用可减少重复逻辑，但必须验证子会话原生重试期间父侧仍等待最终稳定终态，不提前结束委派或交回 writer。具体落点以后续实际代码为准。

## 实施前复核与验收

先在届时使用的 Pi 版本上复现漏匹配；若上游已修复且正常生效，不再增加重复逻辑。问题仍存在时，确认最小方案与操作范围并取得实施授权，再接入现有测试体系。

验证使用禁网 fake provider、临时 Git 与隔离 Pi 配置，同时覆盖单元和真实 Pi 集成：

- 首次断流、下一次成功，无用户追加消息也能继续完成。
- 连续断流严格受原生次数上限约束；关闭自动重试时不强行续跑。
- 重试等待期间取消，以及退出或 reload，不留下迟到续跑。
- 断流前已完成的写入或命令不重复执行；断流消息中未完成的工具调用不执行。
- 非目标错误、工具失败和记录故障不被误分类，原始错误仍可查证。
- 父会话和开发子会话均验证恢复路径；重试不绕过批准、权限与 writer 收尾。

以上均为待验收要求，不是已通过测试。真实模型效果、其他版本和平台不能用 fake provider 结果代替；需要真实 Provider 调用时另行授权。
