# 自适应交付

## 讨论与阶段确认

先读项目规则和唯一进度台账，再核实相关代码、测试与运行事实。区分事实、推断和待验证内容；只追问会影响结果、范围或关键取舍的问题，不规定讨论轮数或固定读量。只读问答不构成写入授权，用户仍想讨论时不催促确认。

父 TUI 的 `delivery_approval` 分别记录以下确认；正文按本次决策写清楚，不复制全文台账或用文件路径、摘要 ID 代替内容：

- `documents`：列明确切 Markdown 路径、编辑用途和文档边界，无须提前重述整套技术方案，不授权源码或命令。
- `design`：说明目标效果、范围、关键设计、验收方向和必要取舍。轻量任务可用简短正文，但不遗漏会改变用户决定的条件。
- `implementation`：给出实施步骤、依赖、验证与停止条件，明确可写路径、固定验收命令及所需容器/只读输入。工具会重新展示已批准的方案原文，不再把同一份方案抄入实施正文。

只在用户准备确认时请求对应阶段。文档授权后可落盘方案草稿；方案确认后编制具体计划，实施确认后才开发。小任务也保留方案和计划，两次阶段确认不合并。若用户未要求暂停且没有未决问题，确认成功后直接衔接下一阶段，不再等待不承载决策的“继续”。拒绝或取消则暂停，不自动重问。模型、子 Agent、工具结果、摘要或旧 Session 不能代替本轮可信批准。

## 文档与证据

篇幅随任务调整：方案记录决策和必要事实，唯一台账记录步骤、当前状态与证据索引，README 面向实际使用。不在多份文档重复维护执行进度，不为既有项目新增第二份 TODO 或 JSON 任务树。每个独立事项核实后及时局部回写，父项未全部验证时保留进行中或阻塞状态。

已有文件修改前读取当前内容并保留用户改动；用 `delivery_document_write` 创建，`delivery_document_edit` 局部修改。每回合只发起一次文档变更，等待原生终态和 writer 交回后继续。核对修改处及其影响；没有新变化、截断或矛盾时，不反复全文读回所有文档。进度更新不能替换批准依据或扩大权限。

父会话仍须核对实际变更、命令结果和审查发现。按工具返回的路径定位相关原始输出、终态或审查正文；信息缺失、内容截断、前后矛盾或现场变化时补充读取，不把子总结当作证据，也不为复述已核实事实反复遍历整份 Session。原生终态与批准核验始终由工具执行，已读内容不能缓存成权限。

长 JSONL 的 grep 匹配行可能在 500 字符处截断，仅适合定位记录。原生环境可用 `read` 按行读取；Structured 未提供 `read` 时，用只读 `exec_command` 在 `node:22-alpine` 中通过 Node `fs` 读取已提供的 Session，按 `\n` 分行并 `JSON.parse`，选择相关 assistant 的 `content.type === "text"` 或 toolResult 正文，按记录位置/字符区间分段输出原文，不输出 thinking。失败后可能只有报错前的正文，不能假定最后一条 assistant 就是完整结论，也不能把重新审查当成读回原证据。

开发自检不替代固定验收。首次执行就保留实际结果；若只缺退出码或摘要，先定位已有原生记录，不为给成功测试补一行说明而重跑。实现或验证条件变化、失败或确有证据缺口时才复验，未运行/失败/取消须如实说明。

## 执行与交付

当前提供原生与 Structured 两种环境的只读工具、父分阶段批准与 Markdown 编辑、受控子开发、本地容器命令、固定候选验收和独立审查；实际能力以工具核实为准。`delivery_readonly` 复用父已启用的原生 `read/grep/find/ls` 或已核实 Structured 的只读容器命令/图片读取，任务需提供目标、必要背景、边界与预期证据，不冒充完整环境重建。

Structured 父与只读/审查子使用只读 worktree，以及工具明确提供的规则、Skill、原始 Session 和审查制品目录（`before/after/diff.patch`），挂载保持原绝对路径，不挂制品父目录。镜像已有 Node 和 BusyBox，不能假定有宿主 `rg`、Python 或 GNU find。`max_output_tokens` 须大于 0 且不超过 12500，默认 4000；`yield_time_ms` 为 0–30000，命令返回 `session_id` 后用 `write_stdin` 取回最终退出，长输出分段读取。

`delivery_develop` 自动附带已批准方案、实施正文、路径与命令；`task` 只补本节点目标、现场事实和预期证据，不复制父历史或再次重述批准全文。按实际风险和可验证片段安排委派，不设固定团队。子不修改父规划文档、不请求批准、不执行宿主 Shell、不继续委派。

需要命令时，在实施提案中提供 `container.image` 和 `container.inputs`，使用不含凭据的本地镜像/只读输入；确认固定镜像 ID，可写挂载沿用 `paths`。子 `bash` 只运行容器 `/bin/sh`，不继承宿主路径或 Shell 配置。无授权则拒绝，不拉取镜像或回退宿主执行。

开发/固定验收容器不挂整个 worktree、HOME、Docker socket、Git/Session、链接或包含保护文件的目录；目标须已存在，新文件在批准目录内创建。单文件挂载不支持父目录原子替换；工具、目录范围、基线/制品或交互不足时报告具体缺口，不伪造 formatter 或验证结果。普通子 `select/confirm/input` 可经父 TUI 回答，但不授予阶段权限；拒绝、取消、超时或交互失败暂停任务。非 TUI、并发问题及多行 editor 不支持。

用 `delivery_validate` 执行原批准命令清单。缺命令、漏跑、非零退出、取消或候选变化均不是通过；候选包含源码/只读输入及元数据、镜像、cwd 和命令，不能排除被 Git 忽略的挂载内容。临时输出放容器 `/tmp`。

按风险使用 `delivery_review`，`task` 只补审查重点和盲点；工具自动提供原批准正文、代码路径、实际差异和原始验收记录。父核对发现并裁决，“审查结束”不等于无问题。明确失败可在原授权内返工，修改后重新验收/审查。子执行实际收尾、父原生结果落盘并取回 writer 后，再回写台账和继续；未知清理或记录状态禁止新写入。

交付说明实际文件、用法、验证结果、兼容性、限制与未执行项，引用必要证据，不重抄全过程。不得自动提交、推送、创建 PR、安装、发布或部署。

## 中断恢复

重载或中断后读方案/唯一台账、核实现场，查看 `/delivery-status` 的磁盘 lease，定位原始 Session 与子执行。正常收尾不自动续跑，旧权限和验收不从日志或摘要恢复；重新确认和验收后才能继续。未知 lease 或工具终态保持只读，不自动解锁、重放或回滚部分结果。
