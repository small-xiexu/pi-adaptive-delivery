仅用于已通过 `/delivery-shape` 启用的交付会话；未启用时提示该入口并停止本提示流程，不自行启用或限制普通 Pi 使用。

按 adaptive-delivery Skill，核对本轮真实方案确认、内部实施计划和现场；有相关唯一台账时读取并按节点推进。开始修改或委派前，先用一行说明本次路径（父 Pi 直接修改 / `delivery_develop` / 是否安排 `delivery_review`）和一句理由。简单任务由父 Pi 直接完成并运行项目已有检查；复杂任务才委派开发子 Agent。每次 `delivery_develop` 或 `delivery_review` 直接提供本节点的 `paths` 和 `inputs`，不再申请实施确认。审查按风险安排，独立检查并主动运行适合项目的检查；过程工具异常和检查结果作为原始执行结果交回父 Pi，由父 Pi 决定返工、继续检查或结束。父 Pi 最终交付时必须列出实际检查命令、退出码和结论；子 Agent 的正常结束不等于检查通过。范围内返工沿用当前方案确认。

没有新变化、失败或证据缺口时，不重复全文读写文档或重跑成功检查，也不再次索要相同范围的批准。只有业务目标、数据行为、对外接口、验收标准或重大外部风险变化时，暂停受影响工作并重新提交 design 提案。取消、权限不足或未知终态时报告断点并暂停；重载/重开按 Skill 核实恢复，不复用旧权限。

若父模型上一轮在方案确认前因 provider 5xx、连接中断或其他回合错误结束，继续时复用当前会话已有方案正文和事实；完整方案直接调用 `delivery_approval` 提交 `design` 提案，不重新做无关调研，不修改代码，不启动子任务。方案不完整时只补齐方案后提交确认。没有持久方案或批准记录时，不能把会话正文当作授权。

方案面板可以选择“提出修改意见”。提交意见后不开发、不审查；读取意见并修订方案后重新确认。确认后每次委派只补当前可验证节点；合并相关的小修复，不因单个工具异常、重复取证或已处理的失败再次创建相同开发任务。`/delivery-tasks` 中的开发、返工和审查是同一方案确认下的累计调用，父会话向用户说明重新调用的原因。
