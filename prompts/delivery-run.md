仅用于已通过 `/delivery-shape` 启用的交付会话；未启用时提示该入口并停止本提示流程，不自行启用或限制普通 Pi 使用。

按 adaptive-delivery Skill，核对本轮真实实施授权、会话中的实施步骤和现场；有相关唯一台账时读取并按节点推进。委派只补当前目标，工具会附带原批准内容；子 Agent 的主状态只表示运行中、已完成或异常退出，过程工具异常和固定命令结果作为原始执行结果交回父 Pi，由父 Pi 决定是否返工、继续验证或结束。核实实际变更和原始证据，完成固定验收、必要独立审查及范围内返工，writer 交回后按需局部回写已有台账。简单任务没有规划文档时直接在会话中交付结果与验证证据，不为执行或收尾补建技术方案、实施计划文件。

没有新变化、失败或证据缺口时，不重复全文读写文档或重跑成功自检，也不再次索要相同范围的批准。范围内修复和原命令复验沿用当前实施授权；固定验收命令自身需要语法或编排修订时，使用 `validationRevisionOf` 引用当前实施批准 ID，`body` 只写修订原因，明确展示前后命令。只有范围、验收意图、额外输入或权限变化才重新提交完整 implementation 提案。取消、权限不足或未知终态时报告断点并暂停；重载/重开按 Skill 核实恢复，不复用旧权限。

实施确认面板可以选择“提出修改意见”。提交意见后不开发、不验收；读取意见并修订实施提案后重新确认。每次委派只补当前可验证节点；合并相关的小修复，不因单个工具异常、重复取证或已处理的失败再次创建相同开发任务。`/delivery-tasks` 中的开发、验收、返工和审查是同一实施批次下的累计调用，父会话向用户说明重新调用的原因。
