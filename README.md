# Pi Adaptive Delivery

基于标准 Pi 的轻量交付编排，不依赖或包装 `pi-subagents`。

**本轮重构已完成限定验收，尚未发布。** 当前支持原生只读工具、受控委派、父 TUI 的分阶段批准、规划文档编辑、子开发、明确授权的容器命令、固定候选验收与独立只读审查。取消、记录失败和重载按原生终态关闭或交接，旧权限和证据不自动恢复。证据包括正式自动化、一次真实模型源码复审及四项返工、用户拒绝场景和授权代理执行的真实 TUI 按键验收，以及一个真实模型驱动的隔离 JSONL CLI 完整正向试用；各自范围见[实施台账](docs/实施计划.md)。这不代表任意项目、插件或桌面体验已验证；未安装到用户全局或真实项目。

## 目标流程

需求澄清与持续讨论 → 方案确认 → 详细计划 → 实施确认 → 按需委派、验证与独立审查 → 范围内返工 → 可验证节点记账 → 交付。

小任务保留简短方案、计划和两次独立阶段确认。确认正文只承载当前决策：文档授权说明编辑用途，方案说明目标与设计，实施说明步骤和执行边界；实施确认工具会同时展示原方案。正常确认后衔接下一阶段，用户要求暂停或有未决问题时等待。方案维护决策、唯一台账维护进度、README 说明用法，避免重复维护相同状态。

- 父 Pi 负责业务判断、证据裁决和唯一 Markdown 进度台账。
- Prompt 与 Skill 提供协作方法，不代替真实用户批准。
- 窄 Extension 管理批准、权限、单 writer、有限委派与必要记录。
- 标准 Pi 负责模型、工具、资源加载、Session、历史、压缩和中止。
- 独立 Agent 用于质疑和取证，不是固定团队或提速配额。

## 当前入口

`/delivery-status` 查看能力、工作区、本进程执行以及磁盘中的真实 lease 归属/记录位置。没有本地执行不等于现场无 writer；记录的 PID 不代表进程一定存活或已经安全停止。`/delivery-shape`、`/delivery-plan`、`/delivery-run` 是协作提示，不能扩大权限。

父模型可使用 `delivery_readonly` 委派一次独立只读分析。父 Extension 管理标准 `pi --mode rpc` 子进程，只开放父会话已启用的原生 `read/grep/find/ls`；子角色不注册父协调工具，不递归委派。结果从正常关闭后的原生 Session 读取并附记录路径，仍须父会话判断证据，不能当作项目完成。

工作区查询固定使用 `/usr/bin/git`。子启动前解析并拒绝工作区内的 Pi 入口或指向项目的链接，以当前工作区外 Node 解释器执行已安装的标准 Pi CLI，不经 PATH 再次寻找 Node；不支持自定义 Shell 包裹入口或备用运行时。路径核验不是可执行文件的原子完整性监控。

任务发送前比对父回合与子 Pi 已加载的工具定义/来源、基础指令、规则正文及 Skill 目录元数据，差异时明确拒绝，不自动复制父临时配置或降级。握手只记录摘要；这不是工具实现代码、Skill 正文或任意插件运行态的完整性证明。配置钩子的实际执行另用隔离测试验证，不承诺任意插件兼容。

用户准备确认时，父模型可通过 `delivery_approval` 分别请求规划文档编辑授权、方案确认和实施确认。正文、路径及操作边界显示在 Pi 原生记录中，由父 TUI 的用户单独选择；确认记录引用当次正文。没有本轮可信方案确认时不能请求实施确认；RPC、JSON、print、子模型或一句“已批准”不能替代该交互。文档授权供专用 Markdown 工具使用；实施确认可明确申请容器命令，不开放宿主 Shell。

正文和确认必须真正写入 Session；无持久 Session 或记录失败不报告成功。重载、换会话或分支导航后授权失效，不从旧记录或压缩摘要生成新授权；需要继续时先读方案/台账、核实现场，再取得本轮确认。文档路径须为明确的 worktree 内 Markdown 文件，不接受目录；实施路径允许明确的文件或目录及其后代。路径按字面解析，不展开 glob。

`delivery_document_write` 创建或完整重写已授权文档，`delivery_document_edit` 通过原生精确匹配修改局部内容。已有文件先读取现场，保留用户内容；不要求标题、围栏或 JSON 计划契约。每回合只进行一次文档变更，待原生工具终态后再开始下一次。父原生 `write/edit/bash` 仍被拒绝，子角色不注册文档工具。

文档读回围绕修改处和信息缺口，不反复全文核对没有变化的材料。父会话仍按返回路径检查相关实际输出、终态和审查发现，不以子总结代替证据；工具每次执行的批准与持久化核验继续生效。成功自检只缺说明、退出码或摘要时先定位已有原始记录，实际变化、失败或证据不足时再复验。

正式入口每次核实工具实际来源，批准核验与 I/O 前检查继续绑定本轮正文、Session、当前分支、工作区和父 lease。同名覆盖不能继承权限，新文档请求或生命周期失效不回退旧范围。活动文档的进度更新本身不撤销批准，也不能扩大权限；核验结果不是可缓存的权限令牌。

父 writer 的 lease 位于当前 worktree 的 Git 元数据目录，不因 Pi 配置目录不同而分裂。文档执行、句柄清理和原生工具结果落盘均核实后才交回；普通编辑失败可在原授权内修正，记录或清理不明时拒绝新写入。取消和在途重载等待 I/O 与原生父回合收尾，部分写入不自动回滚；路径检查不是原子文件系统隔离。限定真实 TUI 按键证据见实施计划 P6.3，跨平台仍未验收。

`delivery_develop` 在本轮文档、方案和实施授权核实后，沿同一 RPC 路径委派一次文件开发。lease 的唯一 owner 真正转移到子 Pi 的 PID/Session/执行 ID；父只保留无写权限的协调身份。子使用受控原生 `edit/write` 创建或精确编辑已授权路径，禁止修改父规划文档、父子执行记录和 Git 元数据，拒绝符号链接与硬链接。子角色标记本身不能取得 writer；父必需工具已被配置覆盖时明确拒绝，不偷偷换成原生实现。

子文件 I/O、容器及句柄清理、子 Session 持久终态和进程关闭核实后，还须父本次原生工具结果唯一落盘，才交回 writer。普通失败可在原授权内再次委派修复；崩溃、记录或清理不明时禁止父子继续写。文件读回不是命令自检，开发自检也不替代固定候选验收。

未发送模型任务、未执行工具的子 Session 可以尚未创建磁盘文件；仅在原控制协议无故障、无在途工具、正常退出且父工具结果落盘时按未执行失败收尾，不伪造子记录。已有任务、消息、执行或不明终态时仍要求原始持久证据。

`delivery_validate` 用同一受控子 Pi 执行实施确认中的非空 `validationCommands`，逐条核实真实容器终态。不能替换、跳序、漏跑或用文字模拟结果；验收子不能 edit/write。源码、只读输入的完整文件树/内容/元数据，以及 cwd、镜像和命令构成候选指纹，全部命令通过且前后候选一致才报告本次验收通过。构建输出宜写容器 `/tmp`；挂载内容即使被 Git 忽略，变化也会使候选失效。

初始候选由父持有 writer 时、启动子进程之前读取一次；缺失目录等准备错误不会先交出 writer，失败落盘后可在原授权内开发并重新验收。子使用该候选的独立副本，父核对返回 receipt 与原始候选，不把准备之后的修改重新当成通过基线。

`delivery_review` 要求本轮已交回 writer 的可信验收，重新核对原始记录、批准和当前候选后启动独立只读子会话。它收到原方案/实施要求、当前代码路径、实际差异及原始验收 Session，不只收到实现者总结；审查期间持父 lease，结束后再核对候选和原验收，最终交接再核实私有绑定的验收引用。证据变化撤销旧验收；最终交接核验失败保留 lease，不能仅凭已返回的审查正文记完成。差异基于固定 `/usr/bin/git` 的原始 HEAD blob 与当前文件副本，调用时以 `--no-replace-objects` 忽略对象替代，不删除替代规则；避免运行项目 clean/textconv/external diff。无 HEAD 用空基线，特殊基线类型或超过 16 MiB 的单文件/差异明确拒绝，不降级假审查。制品保留在返回的临时路径。

工具报告“审查结束”不等于审查通过。父会话裁决发现，范围内返工后重新验收/审查，再取回 writer 局部回写原台账。新验收失败不回退之前的成功；源码、输入、条件、批准或原始证据变化不能沿用旧结论。不对发现做机械评分，也不创建第二份计划。开发与审查工具自动附带原方案和实施正文，`task` 只需补当前节点目标、事实或审查重点。Package 源码复审与新 CLI 的独立审查是不同范围，原始结果见实施计划。

实施提案可增加 `container: { image: "本地镜像名或 ID", inputs: ["额外只读路径"] }`。确认时镜像固定到本地 ID；输入必须明确且不含凭据，可写挂载沿用实施 `paths`。缺镜像不拉取，Docker 客户端须位于工作区外，固定使用本地 `/var/run/docker.sock`、空 Docker 配置和最小环境；不读取登录配置或远端 context。未提供 container 授权时，子 `bash` 也会拒绝。

子 `bash` 在容器中运行 `/bin/sh`，容器 `/workspace` 对应 worktree，工作目录保持相对位置；不继承宿主绝对路径、Shell 配置或完整工具链。仅挂现有输入/写入目标，拒绝整个工作区、规划文档、Git/Session、链接和不明文件类型。新文件需在已授权目录内创建；单文件挂载无法通过父目录原子替换，必要时明确补充目录授权，不扩大隐含权限。镜像和输入须由用户确认不含凭据，Package 不扫描或猜测敏感内容。

一次命令一个容器：无网络、根文件系统只读、非 root、无额外 capabilities、禁止提权，不挂 HOME 或 Docker socket。当前限 300 秒、512 MiB 内存、128 个进程、2 CPU，临时空间 64 MiB，日志使用本地驱动；不是通用资源配置平台。命令失败、取消或超时仍须核实容器终态并删除；引擎失联或清理未知保留引用与 writer，不把客户端退出当成容器停止证明。

只读/开发子的普通 `select/confirm/input` 可由父 TUI 承接，标题标明子 PID；回答只返回本次子请求，不生成方案/实施批准或扩大权限。取消、确认框的“否”、超时或交互错误会暂停当前任务，等待子实际收尾；未决或迟到回答不继续发送。并发问题、非 TUI 父入口及无取消信号的多行 `editor` 明确拒绝，不接管父编辑器/状态栏，也不模拟完整子 TUI。

缺必需能力、协议错误、取消或持久结果缺失不报告成功。宿主门禁不是对插件代码的操作系统沙箱；容器也不隔离已经在宿主加载的插件。候选前后检查不是原子快照，不能阻止绕过 lease 的宿主程序改文件。真实模型质量证据限于已记录任务，不同桌面终端的视觉和输入法体验、真实模型失败返工及所有崩溃窗口未验收。

中断后先核对唯一台账、实际文件、原始 Session 和 `/delivery-status`。正常收尾后的 reload 不自动调用模型，重新确认和验收后可继续；崩溃后的部分文件与未知 lease 保留，不重放未知写入、不仅凭进程退出解锁。未提供自动解锁入口，不能证明原执行及其工具已停止时保持只读。恢复不是日志摘要驱动的自动任务重建。

旧命令、机器契约、Session 和制品不提供兼容、迁移或回退。本次 writer lease 升为 v2，旧记录解析失败保持关闭，不自动迁移或强制释放。不要在运行中的旧任务上切换版本。图表显示复用 Pi，不附带第二套渲染系统。

## 开发验证

当前真实 Pi 证据覆盖 macOS、Node `25.2.1`、Pi `0.85.1`。其他平台和版本未验收；开发依赖类型基线不等于运行兼容认证。

已有离线依赖时：

```sh
npm run typecheck
npm run test:all
git diff --check
```

测试入口使用系统禁网、临时 Git、临时 HOME/agent dir、空凭证与 fake provider。仅仓库源码/依赖及必要祖先元数据可从真实 HOME 读取；其他内容和临时根外写入被拒绝。未提供有效系统隔离时失败退出，不静默跳过。

真实 Docker 验证独立执行：`node --import tsx test/support/run-tests.ts --containers test/container/command.test.ts`。它仅额外允许连接明确的本地 Docker socket，不包含在默认 `test:all` 中；容器本身无网络，仅挂临时假数据。需已运行的本地 Docker 和已缓存、可信且无凭据的 `node:22-alpine`；缺环境报错，不安装、拉取或静默跳过。当前证据为 OrbStack Docker `29.4.0`、Linux/arm64 容器，不代表其他运行时或平台已验收。

不要读取真实 `.npmrc`、凭据或加载用户插件。依赖操作必须离线、禁止安装脚本；缓存不足时暂停，不自行联网。测试制品保留在输出的临时目录中。fake provider 只证明机制，不证明真实模型质量。
