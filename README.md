# Pi Adaptive Delivery

基于标准 Pi 的轻量交付编排，不依赖或包装 `pi-subagents`。

**安装后默认不启用交付约束。** 普通聊天、代码编辑、Shell 和已有插件沿用 Pi 原来的工作方式；输入 `/delivery-shape 你的需求` 才在当前会话启用受控交付。任务收尾后用 `/delivery-exit` 退出，Pi 重载并恢复进入前的工具。退出保留执行记录，不表示任务已通过验收。

**支持原生 Pi 与 `pi-codex-conversion 3.0.29` 的 Structured 模式，尚未发布。** 两种环境共用受控委派、父 TUI 的分阶段批准、规划文档编辑、子开发、明确授权的容器命令、固定候选验收与独立只读审查。取消、记录失败和重载按原生终态关闭或交接，旧权限和证据不自动恢复。两种环境均有真实模型、真实 TUI 批准及隔离 CLI 开发、审查返工和交付证据；自动化回归使用 fake provider。各自范围、试用缺口及最新验证见[实施台账](docs/实施计划.md)。真实项目已通过本地 Package 接入试用，完整项目交付尚待验证。

## 目标流程

需求澄清与持续讨论 → 方案确认 → 实施步骤与验收说明 → 实施确认 → 按需委派、验证与独立审查 → 范围内返工 → 交付；需要持续跟踪时维护唯一台账。

用 `/delivery-shape 你的需求` 启用并开始对齐；不带需求时只启用，不调用模型。AI 先核实项目事实，再逐次提出影响本次交付的关键问题，每次一个，并附推荐和理由；你可以回答“按推荐”。AI 根据回答调整方案和下一问，关键条件清楚后就整理方案，不追问纯实现偏好或未来扩展；明确需求可以零追问，你仍想讨论时可继续。普通自然语言需求不会自动启用该流程。

**简单明确、可一次完成并验证的需求，不强制创建技术方案和实施计划文件。** 直接在会话中简短说明方案、实施步骤与验证方式，仍分别确认方案和实施；两次正文及执行证据保存在 Pi 原生会话中。需要持续维护设计决策、跟踪多个依赖步骤或分阶段交付时再落文档，已有相关方案/台账按项目规则沿用。由 AI 按实际需要判断，不按改动行数评分，不增加文档确认或任务模式开关。

任务需要的 Markdown 默认可由父会话创建或修订，无须单独批准编辑权限。方案确认说明目标与设计，实施确认说明步骤和执行边界，其详情可查看原方案。正常确认后衔接下一阶段，用户要求暂停或有未决问题时等待。需要文档时，方案维护决策、唯一台账维护进度、README 说明用法；无文档简单任务直接交付结果与验证证据，不为收尾补建文件。

- 父 Pi 负责业务判断、证据裁决，并按需维护已有唯一 Markdown 进度台账。
- 子任务卡片默认两行显示真实状态、简短目标与当前操作。全屏模式点击卡片，或输入 `/delivery-tasks` 选择任务，可查看连续实时输出；Esc 只关闭详情，任务继续运行。普通模式使用命令入口；Ctrl+O 仍可展开近期预览。
- Prompt 与 Skill 提供协作方法，不代替真实用户批准。
- 窄 Extension 管理批准、权限、单 writer、有限委派与必要记录。
- 标准 Pi 负责模型、工具、资源加载、Session、历史、压缩和中止。
- 独立 Agent 用于质疑和取证，不是固定团队或提速配额。

## 当前入口

使用 Pi 0.85.1 或更新版本。在可信项目的 `.pi/settings.json` 中保留已有配置，加入本地 Package 路径，例如：

```json
{
  "packages": ["/absolute/path/to/pi-adaptive-delivery"]
}
```

加载后可以继续普通使用；`/delivery-status` 会提示交付未启用。调用 `/delivery-shape` 后才启用门禁，`bash/edit/write` 不再授予父模型源码写入或宿主执行权限，开发走受控子会话。Pi 默认四工具不包含 `grep/find/ls`，进入交付后原生只读可能只剩 `read`；需要仓库查找时，在已有 `defaultTools` 中按需加入 `grep/find/ls`。项目数组会替换全局数组，请保留原工具选择；Package 不自动启用停用的查找工具。

**用户在父 TUI 手动输入的 `!命令`、`!!命令` 保留 Pi 原生行为**，例如 `!pwd`，无须交付批准。Shell 配置、输出、退出码、取消及 `!!` 不进入模型上下文的语义由 Pi 和已有 Shell 扩展处理。交付启用期间，人工命令不取得 AI 权限、不成为固定验收证据，也不由交付 writer lease 调度；手动修改代码后仍按实际候选核验。门禁仅在交付启用后约束父 AI 工具调用、RPC bash 及受控子会话。

原生 `find` 需要可用的 `fd`（或 `fdfind`），`grep` 需要 `rg`；可以来自 PATH 或 Pi 已缓存工具。离线环境应事先准备，缺失时 Pi 会报错；仅看到工具名称不代表底层可执行文件已就绪。

`/delivery-status` 不会启用交付；启用后查看当前工具模式、运行任务及需要处理的事项，`details` 提供原执行和磁盘 lease 的诊断信息。现场有未交回写入记录时会提示暂停写入，没有本地任务不等于原执行已停止。`/delivery-plan`、`/delivery-run` 只提供已启用流程中的协作提示，不启用流程或扩大权限。

`/delivery-exit` 要求当前回合、排队消息、批准交互及文件/容器操作均已收尾，且没有未交回 writer 或残留操作锁；条件不明时说明原因并保持约束，不强制解锁。正常退出通过 Pi 原生重载恢复工具实现和进入前的启用集合，保留文件及历史记录。重新调用 `/delivery-shape` 可开始下一轮，两次确认仍独立。

启用选择保存在 Pi 原生 Session 中：重载或重开已启用会话会继续受控，旧批准与验收仍不恢复；新建普通会话不自动启用。首次模型响应前，Pi 可能尚未把新 Session 写到磁盘，无持久记录的新会话不能当作可恢复任务。旧版本没有启用记录的会话不自动接管，请在旧任务正常收尾后切换版本。

方案整理好后，在底部审阅区直接输入修改意见：Enter 发送，Shift+Enter 换行；AI 修订方案正文、说明变化后再请你审阅，有文件时同步修改同一份文件，可反复调整。准备好了再按 Tab 切到操作区，用 ↑↓ 选择“确认方案”。空回车不会批准，确认方案后才准备实施步骤与验收说明，实施仍需单独确认。

选择“稍后再看”或按 Esc 可关闭审阅、恢复普通输入，方案与已发送意见保留。之后输入“继续看方案”、直接提出意见，或用 `/delivery-resume` 恢复当前分支最近未确认的方案审阅。恢复时 AI 核对会话正文、已有意见和现场，有文件时先读最新内容；不因恢复补建规划文件，也不直接批准旧方案或开始开发。重载、重开原会话后仍可讨论修订，开发前须重新取得方案与实施确认。

两次阶段确认均显示在底部输入区。方案审阅用 Ctrl+O 查看完整提案、PgUp/PgDn 滚动；Tab 切换意见输入与操作区，操作默认“稍后再看”。实施确认用 Tab 查看详情，↑↓ 选择、Enter 确认、Esc 取消，默认“暂不批准”。

任务详情默认展示连续输出，每秒刷新，跟随最新行；向上翻阅会暂停跟随，按 End 或回到底部恢复。工具执行中即可查看已收到的输出，Esc 只关闭详情，子任务继续运行。程序尚未输出的内容无法提前显示；过长的在途输出保留最近片段并提示，完成后读取原始结果。

详情不再分“工具过程”和“结果”页签，工具输出与公开正文连续显示，最终失败原因直接附在其中。长正文支持 ↑↓、PgUp/PgDn、滚轮和 Home/End；Enter 查看完整任务、模型选择理由与原记录路径，再按 Enter 或 Backspace 返回实时输出。刷新保留阅读位置，关闭后停止刷新，结束后仍可查看。只展示公开正文和工具记录，不展示 thinking；原记录缺失或末行未完整会明确提示，详情不恢复权限或改变任务结果。

父模型使用 `delivery_git_status({})` 查看当前 worktree 的分支、HEAD 和既有改动。它固定执行系统 Git，不接受任意命令或路径，禁用项目 fsmonitor 与内容过滤器，不更新 index；不提供源码 diff。子模块只报告提交指针变化，其内部改动需要另查。返回路径按 JSON 转义，超出 50 KiB 的结果会明确失败，不能把清单缺失当作工作区干净。

父模型可使用 `delivery_readonly` 委派一次独立只读分析。父 Extension 管理标准 `pi --mode rpc` 子进程，使用父会话已启用的原生 `read/grep/find/ls`，或下述 Structured 只读工具；子角色不注册父协调工具，不递归委派。结果从正常关闭后的原生 Session 读取并附记录路径，仍须父会话判断证据，不能当作项目完成。失败也返回已知原始记录及进程/工具/持久收尾事实，父可据此取证。

普通只读、开发和审查正常结束且收尾核实后，如过程中有工具错误，显示“已结束，有工具错误待核对”，卡片使用提醒色。父会话核对原始错误、后续操作及最终产物，再决定返工或继续验证；这不表示错误已修复或任务已验收，也不自动重跑委派。原工具错误保持原样，固定验收中的工具失败、用户取消、协议/记录异常与收尾不明仍报告失败。

父 AI 按任务目的、复杂度和风险选择子任务模型与推理级别，14 类工作场景的建议见 [Skill](skills/adaptive-delivery/SKILL.md)。`delivery_models({})` 查询 Pi 当前可用模型及支持级别；四类委派均可附加 `agent`，例如 `{"thinking":"medium","reason":"边界明确的局部开发"}`，也可指定 `model: { provider, id }`。省略的模型或级别继承父会话；未配置模型、不支持的级别及子实际启动值不符均明确拒绝，不自动降级。此选择只影响本次子任务，父模型保持不变；卡片显示实际模型和级别，详情显示选择理由，不统计费用或 token。新选择机制以禁网 fake provider 验证，不代表真实模型质量或节省效果已验证。

工作区查询固定使用 `/usr/bin/git`。子启动前解析并拒绝工作区内的 Pi 入口或指向项目的链接，以当前工作区外 Node 解释器执行已安装的标准 Pi CLI，不经 PATH 再次寻找 Node；不支持自定义 Shell 包裹入口或备用运行时。路径核验不是可执行文件的原子完整性监控。

任务发送前比对父回合与子 Pi 已加载的工具定义/来源、基础指令、规则正文及 Skill 目录元数据，差异时明确拒绝，不自动复制父临时配置或降级。握手只记录摘要；这不是工具实现代码、Skill 正文或任意插件运行态的完整性证明。配置钩子的实际执行另用隔离测试验证，不承诺任意插件兼容。

父模型通过 `delivery_approval` 请求方案审阅和实施确认。方案正文可供审阅时即可展示，用户可反馈、暂停或确认；实施在用户准备确认时请求。正文、路径及操作边界显示在 Pi 原生记录中，由父 TUI 的用户单独选择；确认记录引用当次正文。没有本轮可信方案确认时不能请求实施确认；RPC、JSON、print、子模型或一句“已批准”不能替代该交互。方案 `paths` 列明本任务由父维护的规划 Markdown 文件，随方案确认冻结，供子开发和容器保护；没有规划文档时传 `[]`，无需占位文件，不得遗漏已有需维护的方案/台账。实施 `paths` 必须为非空的可写文件或目录，可明确申请容器命令，不开放宿主 Shell；旧 `documents` 阶段已删除。

实施确认先显示实际可写路径、操作边界和环境，再列本次说明；详情可核对完整正文、镜像、只读输入、固定命令及原方案。计划修改几个文件与工具可写哪些目录分开展示，缩略说明不替换原生批准快照。有方案文件时，审阅正文先给路径和修改摘要；意见保存在原生工具结果中，发送意见不会形成批准。

正文和确认必须真正写入 Session；无持久 Session 或记录失败不报告成功。重载、换会话或分支导航后授权失效，不从旧记录或压缩摘要生成新授权；需要继续时先核对原始方案/实施正文、已有相关文档和现场，再取得本轮确认。列明的文档路径须为明确的 worktree 内 Markdown 文件，不接受目录；实施路径允许明确的文件或目录及其后代。路径按字面解析，不展开 glob。

父 TUI 的 `delivery_document_write` 默认可创建或完整重写 worktree 内明确路径的 Markdown 文档，`delivery_document_edit` 通过原生精确匹配修改局部内容。已有文件先读取现场，保留用户内容；不要求标题、围栏或 JSON 计划契约。每回合只进行一次文档变更，待原生工具终态后再开始下一次。源码、Git/Session 和链接路径仍受保护；父原生 `write/edit/bash` 仍被拒绝，子角色不注册文档工具。

文档读回围绕修改处和信息缺口，不反复全文核对没有变化的材料。父会话仍按返回路径检查相关实际输出、终态和审查发现，不以子总结代替证据；工具每次执行的批准与持久化核验继续生效。成功自检只缺说明、退出码或摘要时先定位已有原始记录，实际变化、失败或证据不足时再复验。

正式入口每次核实工具实际来源，I/O 前检查绑定本次原生调用、目标路径、Session、当前分支、工作区和父 lease。同名覆盖不能继承权限，生命周期变化取消在途操作。活动文档的进度更新本身不撤销方案/实施批准，也不能扩大源码或命令权限；核验结果不是可缓存的权限令牌。

父 writer 的 lease 位于当前 worktree 的 Git 元数据目录，不因 Pi 配置目录不同而分裂。文档执行、句柄清理和原生工具结果落盘均核实后才交回；普通编辑失败可修正，记录或清理不明时拒绝新写入。取消和在途重载先取消文档 I/O，再等待 I/O 与原生父回合收尾，部分写入不自动回滚；路径检查不是原子文件系统隔离。历史限定真实 TUI 按键证据见实施计划 P6.3，新默认编辑机制使用模拟 TUI 验证，跨平台仍未验收。

`delivery_develop` 在本轮方案和实施确认核实后，沿同一 RPC 路径委派一次文件开发。lease 的唯一 owner 真正转移到子 Pi 的 PID/Session/执行 ID；父只保留无写权限的协调身份。子使用受控原生 `edit/write` 创建或精确编辑已授权路径，禁止修改方案中列明的父规划文档、父子执行记录和 Git 元数据，拒绝符号链接与硬链接。子角色标记本身不能取得 writer；父必需工具已被配置覆盖时明确拒绝，不偷偷换成原生实现。

子文件 I/O、容器及句柄清理、子 Session 持久终态和进程关闭核实后，还须父本次原生工具结果唯一落盘，才交回 writer。普通失败可在原授权内再次委派修复；崩溃、记录或清理不明时禁止父子继续写。文件读回不是命令自检，开发自检也不替代固定候选验收。

未发送模型任务、未执行工具的子 Session 可以尚未创建磁盘文件；仅在原控制协议无故障、无在途工具、正常退出且父工具结果落盘时按未执行失败收尾，不伪造子记录。已有任务、消息、执行或不明终态时仍要求原始持久证据。

`delivery_validate` 用同一受控子 Pi 执行实施确认中的非空 `validationCommands`，逐条核实真实容器终态。不能替换、跳序、漏跑或用文字模拟结果；验收子不能 edit/write。源码、只读输入的完整文件树/内容/元数据，以及 cwd、镜像和命令构成候选指纹，全部命令通过且前后候选一致才报告本次验收通过。构建输出宜写容器 `/tmp`；挂载内容即使被 Git 忽略，变化也会使候选失效。

初始候选由父持有 writer 时、启动子进程之前读取一次；缺失目录等准备错误不会先交出 writer，失败落盘后可在原授权内开发并重新验收。子使用该候选的独立副本，父核对返回 receipt 与原始候选，不把准备之后的修改重新当成通过基线。

`delivery_review` 要求本轮已交回 writer 的可信验收，重新核对原始记录、批准和当前候选后启动独立只读子会话。它收到原方案/实施要求、当前代码路径、实际差异及原始验收 Session，不只收到实现者总结；审查期间持父 lease，结束后再核对候选和原验收，最终交接再核实私有绑定的验收引用。证据变化撤销旧验收；最终交接核验失败保留 lease，不能仅凭已返回的审查正文记完成。差异基于固定 `/usr/bin/git` 的原始 HEAD blob 与当前文件副本，调用时以 `--no-replace-objects` 忽略对象替代，不删除替代规则；避免运行项目 clean/textconv/external diff。无 HEAD 用空基线，特殊基线类型或超过 16 MiB 的单文件/差异明确拒绝，不降级假审查。制品保留在返回的临时路径。

工具报告“审查结束”不等于审查通过。父会话裁决发现，范围内返工后重新验收/审查，再取回 writer 局部回写原台账。新验收失败不回退之前的成功；源码、输入、条件、批准或原始证据变化不能沿用旧结论。不对发现做机械评分，也不创建第二份计划。开发与审查工具自动附带原方案和实施正文，`task` 只需补当前节点目标、事实或审查重点。Package 源码复审与新 CLI 的独立审查是不同范围，原始结果见实施计划。

实施提案可增加 `container: { image: "本地镜像名或 ID", inputs: ["额外只读路径"] }`。确认时镜像固定到本地 ID；输入必须明确且不含凭据，可写挂载沿用实施 `paths`。缺镜像不拉取，Docker 客户端须位于工作区外，固定使用本地 `/var/run/docker.sock`、空 Docker 配置和最小环境；不读取登录配置或远端 context。未提供 container 授权时，子 `bash` 也会拒绝。

子 `bash` 在容器中运行 `/bin/sh`，容器 `/workspace` 对应 worktree，工作目录保持相对位置；不继承宿主绝对路径、Shell 配置或完整工具链。仅挂现有输入/写入目标，拒绝整个工作区、规划文档、Git/Session、链接和不明文件类型。新文件需在已授权目录内创建；单文件挂载无法通过父目录原子替换，必要时明确补充目录授权，不扩大隐含权限。镜像和输入须由用户确认不含凭据，Package 不扫描或猜测敏感内容。

一次命令一个容器：无网络、根文件系统只读、非 root、无额外 capabilities、禁止提权，不挂 HOME 或 Docker socket。当前限 300 秒、1 GiB 内存、128 个进程、2 CPU，临时空间 64 MiB，日志使用本地驱动；没有通用资源配置面。原生 bash 的 timeout 默认也是 300 秒，测试耗时未知时省略该参数。异常错误正文保留真实退出码、清理状态、时限及最多 8000 字符的输出尾部，未取得的事实明确标注。命令失败、取消或超时仍须核实容器终态并删除；引擎失联或清理未知保留引用与 writer，不把客户端退出当成容器停止证明。

只读/开发子的普通 `select/confirm/input` 可由父 TUI 承接，标题标明子 PID；回答只返回本次子请求，不生成方案/实施批准或扩大权限。取消、确认框的“否”、超时或交互错误会暂停当前任务，等待子实际收尾；未决或迟到回答不继续发送。并发问题、非 TUI 父入口及无取消信号的多行 `editor` 明确拒绝，不接管父编辑器/状态栏，也不模拟完整子 TUI。

模型返回确切的 `stream_read_error` 时，父子会话均交由 Pi 原生策略重试，成功后继续当前任务。沿用 `retry.enabled`、`retry.maxRetries` 和 `retry.baseDelayMs`，不强制开启；取消或次数耗尽后停止。原始错误保留，不补发用户“继续”、不主动重放已经完成的工具或整项委派。此能力已用禁网 fake provider、真实 Pi 和实际容器命令定向验证，不代表底层网络断流已消除。

缺必需能力、协议错误、取消或持久结果缺失不报告成功。宿主门禁不是对插件代码的操作系统沙箱；容器也不隔离已经在宿主加载的插件。候选前后检查不是原子快照，不能阻止绕过 lease 的宿主程序改文件。真实模型质量证据限于已记录任务；已知工具失败后的自主取证、CLI 源码缺陷返工已有定向证据，各桌面终端视觉和输入法体验及所有崩溃窗口仍未完整验收。本轮未调用真实模型验证断流恢复效果。

中断后先核对实际文件、原始 Session、已有相关方案/唯一台账和 `/delivery-status`；无规划文档的任务从原始会话正文与执行证据核对，记录不足时说明缺口。正常收尾后的 reload 不自动调用模型，重新确认和验收后可继续；崩溃后的部分文件与未知 lease 保留，不重放未知写入、不仅凭进程退出解锁。未提供自动解锁入口，不能证明原执行及其工具已停止时保持只读。恢复不是日志摘要驱动的自动任务重建。

旧命令、机器契约、Session 和制品不提供兼容、迁移或回退。本次 writer lease 升为 v2，旧记录解析失败保持关闭，不自动迁移或强制释放。不要在运行中的旧任务上切换版本。图表显示复用 Pi，不附带第二套渲染系统。

## Structured 接入

未启用交付时，Package 不接管 Structured 工具。需要受控交付时，当前核实 `@howaboua/pi-codex-conversion 3.0.29` 的正式入口与 Structured（`executionMode: "normal"`）模式；**实际加载顺序必须为 delivery-gate 在前、pi-codex-conversion 在后**。在管理两者的同一 Pi `packages` 列表中调整顺序并保留其他配置；如果插件已在全局列表中先加载，只向项目追加本 Package 不足以改变顺序。使用已安装的本地 Package 路径即可，无须重新安装插件。调用 `/delivery-shape` 后以 `/delivery-status` 确认 Structured 工具已接管，未接管时受控工具拒绝执行；正常 `/delivery-exit` 重载后恢复原插件实现。

插件自己的工具 schema、系统提示及 request/context hooks 保持启用。交付扩展通过公开工具注册接管 `exec_command/write_stdin/apply_patch/view_image` 的执行，复用原批准、writer 和 Docker 生命周期；不导入 Pi 或插件内部执行模块、不修改插件安装。父子核对相同来源/定义和模式，子保留独立上下文。Code/Notebook 不在本轮支持范围，不能通过切换它们获得宿主执行权限。

- 父与普通只读/审查子：Shell 使用已有本地 `node:22-alpine`，整棵工作树只读，并挂载明确的规则、Skill 和原始证据；这些额外资源仍只读。本次审查制品目录包含 `before/after/diff.patch`，由现有委派记录明确引用，成功或失败后父均可读取；不挂其父目录或邻接资源。不挂宿主 HOME、网络或 socket，发现挂载内 IPC/设备则拒绝。父 `apply_patch` 被拒绝，规划文档使用默认可编辑 Markdown 的 `delivery_document_edit/write`。
- 开发/固定验收子：必须在实施确认中提供本地容器镜像与明确输入/写入路径。`apply_patch` 在相同挂载内运行该版本附带的 Linux helper，支持多文件新增、编辑、移动和删除；镜像需具备对应架构的 glibc loader，例如已验证的 `python:3.12-slim`。越界补丁失败可能留下范围内的部分修改，按真实文件核对，不自动回滚。
- 命令使用容器内 `/bin/sh` 和已有程序，workdir 与挂载文件保持本 worktree 原绝对路径。只读镜像提供 Node 和 BusyBox，不能假定有宿主 `rg`、Python 或 GNU find。至多一个未交回命令；`exec_command` 返回 `session_id` 后用 `write_stdin` 轮询，`tty: true` 才可输入。`max_output_tokens` 须大于 0 且不超过 12500，默认 4000；`yield_time_ms` 为 0–30000。沿用每命令 300 秒及原资源上限，长输出分段读取；固定验收同步等实际退出，不允许换 Shell、工作目录或使用 PTY。非零退出码保留在 Structured 原生结果中，固定验收据实际退出码判断失败。
- 命令只在当前回合/子任务内存续；回合结束、取消或会话关闭会停止未交回命令并核实容器。未通过原生工具交回的子命令不能成为成功交付，未知清理保留 writer。跨会话 ID 不恢复。`view_image` 使用 Pi 原生图片读取，需要可接收图片的模型，不另调 Provider 做文本描述。

这不继承宿主已安装程序、Shell 配置或登录状态。读取及开发镜像须事先准备，缺失或不适配时明确失败，不自动拉取或回退到宿主。已加载插件仍是可信宿主代码，容器限制的是模型命令；外部程序并发改挂载内容或创建 IPC 不属于原子隔离保证。

原生 `grep` 会截断超过 500 字符的匹配行，适合定位 JSONL 记录。Structured 没有 `read` 时，可在只读 `exec_command` 中用 Node `fs` 按 `\n` 分行、逐条 `JSON.parse`，按角色/记录位置选取 assistant 的 text 或 toolResult 正文，再按字符区间输出；不输出 thinking，不把截断行或重新审查当作完整原证据。工具失败后也可能留下报错前的正文，不能只看最后一条 assistant 消息。取证只读回已有记录，不恢复旧批准或改写原始错误。

只读子不预挂自身仍在追加的 Session；父在子收尾后按委派引用读取原记录，避免已挂载活动文件的旧内容影响交接取证。不复制成另一份日志，也不自动重试读取；任意宿主文件共享的实时一致性不在保证范围内。

## 开发验证

当前真实 Pi 证据覆盖 macOS、Node `25.2.1`、Pi `0.85.1`。其他平台和版本未验收；开发依赖类型基线不等于运行兼容认证。

已有离线依赖时：

```sh
npm run typecheck
npm run test:all
git diff --check
```

测试入口使用系统禁网、临时 Git、临时 HOME/agent dir、空凭证与 fake provider。仅仓库源码/依赖及必要祖先元数据可从真实 HOME 读取；其他内容和临时根外写入被拒绝。未提供有效系统隔离时失败退出，不静默跳过。

真实 Docker 验证独立执行：`node --import tsx test/support/run-tests.ts --containers test/container/command.test.ts`。它仅额外允许连接明确的本地 Docker socket，不包含在默认 `test:all` 中；容器本身无网络，仅挂临时假数据。需已运行的本地 Docker 和已缓存、可信且无凭据的 `node:22-alpine`；缺环境报错，不安装、拉取或静默跳过。当前证据为 OrbStack Docker `29.4.0`、Linux/arm64 容器，不代表其他运行时或平台已验收。

Structured 正式验证：`node --import tsx test/support/run-tests.ts --containers --adapter /absolute/path/to/pi-codex-conversion test/structured/flow.test.ts`。仅此显式入口额外允许读取已安装插件的代码依赖，不读取真实配置/认证；需两个上述本地镜像。覆盖完整流程、请求/上下文增强、PTY、补丁、并发只读、会话切换、越界、取消及未知终态；每个场景核对自己创建的容器和子 PID。未调用真实 Provider，也未执行新的真实 TUI 批准按键或证明模型质量/费用改善。

不要读取真实 `.npmrc`、凭据或加载未明确选定的用户插件。依赖操作必须离线、禁止安装脚本；缓存不足时暂停，不自行联网。测试制品保留在输出的临时目录中。fake provider 只证明机制，不证明真实模型质量。
